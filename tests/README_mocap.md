# 动捕模块测试

全部使用模拟 SteamVR / DG-LAB 客户端和离屏 Qt 界面，不注册真实 SteamVR 清单，不给实际设备发送命令，不改用户的动捕配置。

在项目根目录运行：

```powershell
./.venv/Scripts/python.exe -m pytest tests/test_mocap.py tests/test_mocap_worker.py tests/test_mocap_tab.py tests/test_mocap_controller.py -q
```

| 文件 | 覆盖范围 |
| --- | --- |
| `test_mocap.py` | 清单注册、按序列号保存名称、配置校验和原子写入失败、速度和角速度计算、旋转跨越 180°/360°、瞬移和数据异常、失去追踪及重连、不同设备独立计时、丢帧、旧触发失效 |
| `test_mocap_worker.py` | Runtime 缺失、注册后重启、退出事件、读取失败、关闭 Runtime、采样通知不积压 |
| `test_mocap_tab.py` | 采样到倒计时和通道请求的集成、数据过期、恢复后重计时、排队及执行中的定时请求失效、重连旧消息、规则编辑和改名后的设备重排 |
| `test_mocap_controller.py` | 实际异步命令队列配合模拟客户端；A/B 限幅、恢复基线、手动接管、SPS/ToN 优先级、定时结束及重叠、取消与异步锁竞争、设备写入失败、长期命令记录增长 |

触发等待时间只累计连续、有效的采样。追踪器失去追踪或消失时，其等待状态立即删除，恢复后从零开始，不影响其他正常追踪器。数据整体中断、过期或界面积压导致漏帧时，无法确认连续性，因此重置全部等待，并取消动捕输出。采样超时为 `max(0.25 秒, 2.5 / 采样频率)`，看门狗每 100 ms 检查一次。

这里的等待时间指速度/角速度上下限的触发等待。已经成功启动的固定时长开火仍使用原来的持续时间语义；单个追踪器丢失不会暂停并延长已经发出的固定时长开火。尚未启动的旧请求会失效。

## 性能复测

```powershell
./.venv/Scripts/python.exe scripts/benchmark_mocap.py --sensors 16 --frames 1000
./.venv/Scripts/python.exe scripts/benchmark_mocap.py --sensors 64 --frames 1000
```

本机 Python 3.14.3 / PySide6 6.11.2，模拟 30 Hz、每设备四条规则，预热 50 帧后测量 1000 帧：

| 设备数 | 姿态计算+规则+数据交接 平均 / P95 | 界面更新+离屏绘制 平均 / P95 |
| --- | --- | --- |
| 16 | 0.190 / 0.277 ms | 0.792 / 1.232 ms |
| 64 | 0.643 / 0.933 ms | 2.185 / 2.455 ms |

这是合成负载测量，不含原生 OpenVR 调用、硬件通讯、窗口合成器或 VRChat 帧时间，也不代表帧耗时上限。64 设备压力测试中界面单次最大值约 26.6 ms。采样线程只保留一个待消费快照；规则判断与设备数成线性关系；表格不再每次刷新重复设置字体。真实驱动卡顿、USB/蓝牙延迟及游戏内帧率需用实际设备验证。
